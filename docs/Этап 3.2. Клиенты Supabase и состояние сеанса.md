# Этап 3.2. Клиенты Supabase и состояние сеанса

**Файл документа:** `docs/stages/stage_03_2_supabase_clients.md`
**Новые файлы:** `web/src/lib/env.ts`, `web/src/lib/supabase/server.ts`,
`web/src/lib/supabase/client.ts`, `web/src/app/diag/page.tsx`
**Основание:** ТЗ v1.0, раздел 6 (S4, S5, S6), 8, 9 (D3)

---

## 1. Цель и результат этапа

Подключить приложение к **удалённому** проекту Supabase: установить библиотеки,
создать модуль проверки переменных окружения, серверный и браузерный клиенты,
а также диагностическую страницу, показывающую состояние сеанса и фактическую
видимость данных.

**Результат:** страница `/diag` открывается без входа и показывает отсутствие
сеанса и отказ в доступе ко всем объектам данных. Это подтверждает, что
публичный ключ сам по себе данных не открывает.

Вход пользователя и защита маршрутов — этап 3.3.

---

## 2. Предварительные условия

1. Этап 3.1 (редакция 2) выполнен: каркас создан, `npm run check:supabase`
   выводит два сообщения `[ОК]`.
2. Файл `web/.env.local` содержит адрес облачного проекта и публичный ключ.
3. Команды выполняются из каталога `web/`.

## 3. Проектные решения

| Решение | Обоснование |
|---|---|
| Два клиента: серверный и браузерный | Серверный работает с cookie-сеансом и используется в серверных компонентах; браузерный — только в клиентских компонентах. Смешение приводит к утечке сеанса и ошибкам сборки. |
| Серверный модуль помечен пакетом `server-only` | Сборка завершится ошибкой при случайном импорте серверного кода в клиентский компонент. Ошибка выявляется сразу, а не во время исполнения. |
| На сервере применяется `getUser()`, а не `getSession()` | `getSession()` читает cookie без проверки подписи токена. `getUser()` обращается к серверу аутентификации и подтверждает подлинность сеанса (ТЗ, S6). |
| Cookie передаются методами `getAll` / `setAll` | Построчные `get`/`set`/`remove` устарели в `@supabase/ssr`; парная схема корректно обрабатывает обновление и продление токена. |
| Запись cookie обёрнута в `try/catch` | В серверных компонентах Next.js запись cookie запрещена. Обновление сеанса возьмёт на себя промежуточный слой (этап 3.3); до его появления исключение подавляется осознанно. |
| Проверка переменных окружения вынесена в отдельный модуль | Отсутствие значения выявляется при старте с понятным сообщением, а не при первом запросе. |
| Обращения к `process.env` записаны явно | Значения с префиксом `NEXT_PUBLIC_` подставляются сборщиком по буквальному имени; динамическое обращение `process.env[имя]` в браузере не работает. |
| Диагностическая страница динамическая | Она читает cookie и не должна попадать в статическую сборку. |
| Секретный ключ не используется | Все запросы выполняются от имени анонимной роли или пользователя; политики RLS действуют одинаково (ТЗ, S4). |

## 4. Пошаговое выполнение

### Шаг 3.2.1. Установка библиотек

```bash
npm install @supabase/supabase-js @supabase/ssr server-only
npm ls @supabase/supabase-js @supabase/ssr server-only
```

Версии фиксируются в `package-lock.json`. Пакет `server-only` не содержит
исполняемого кода: он служит признаком для сборщика.

### Шаг 3.2.2. Модуль переменных окружения

Файл `web/src/lib/env.ts`.

```ts
/**
 * Проверка параметров подключения к удалённому Supabase.
 *
 * Значения задаются в web/.env.local (локально) и в настройках Vercel (этап 4).
 * Здесь допускаются только публичные переменные: они попадают в браузер.
 * Секретный ключ в приложении не используется (ТЗ, S4).
 */

// Обращения записаны буквально: сборщик подставляет значения по имени.
const supabaseUrl = process.env.NEXT_PUBLIC_SUPABASE_URL;
const supabasePublicKey = process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY;

if (!supabaseUrl || !supabasePublicKey) {
  throw new Error(
    "Не заданы NEXT_PUBLIC_SUPABASE_URL и NEXT_PUBLIC_SUPABASE_ANON_KEY. " +
      "Заполните web/.env.local (этап 3.1, шаг 3.1.7) и перезапустите сервер."
  );
}

// Стенд работает только с облачным проектом: локальный стек не предусмотрен.
if (/localhost|127\.0\.0\.1|:54321/i.test(supabaseUrl)) {
  throw new Error(
    "Указан локальный адрес Supabase. Требуется адрес облачного проекта вида https://<ref>.supabase.co."
  );
}

export const SUPABASE_URL = supabaseUrl;
export const SUPABASE_PUBLIC_KEY = supabasePublicKey;

/** Хост проекта для отображения в диагностике; ключ не выводится. */
export const SUPABASE_HOST = new URL(supabaseUrl).host;
```

### Шаг 3.2.3. Серверный клиент

Файл `web/src/lib/supabase/server.ts`.

```ts
import "server-only";

import { cookies } from "next/headers";
import { createServerClient } from "@supabase/ssr";
import { SUPABASE_URL, SUPABASE_PUBLIC_KEY } from "@/lib/env";

/**
 * Клиент для серверных компонентов, серверных действий и обработчиков маршрутов.
 *
 * Сеанс хранится в cookie, поэтому каждый запрос к базе данных выполняется
 * с токеном пользователя, и политики RLS применяются на стороне базы данных.
 *
 * В Next.js 15 функция cookies() асинхронная — отсюда await.
 */
export async function createSupabaseServerClient() {
  const cookieStore = await cookies();

  return createServerClient(SUPABASE_URL, SUPABASE_PUBLIC_KEY, {
    cookies: {
      // Чтение всех cookie сеанса.
      getAll() {
        return cookieStore.getAll();
      },

      // Запись cookie возможна в серверных действиях и обработчиках маршрутов.
      // В серверных компонентах она запрещена — исключение подавляется:
      // продление сеанса выполняет промежуточный слой (этап 3.3).
      setAll(cookiesToSet) {
        try {
          for (const { name, value, options } of cookiesToSet) {
            cookieStore.set(name, value, options);
          }
        } catch {
          // Намеренно пусто: компонент только читает данные.
        }
      },
    },
  });
}
```

### Шаг 3.2.4. Браузерный клиент

Файл `web/src/lib/supabase/client.ts`.

```ts
import { createBrowserClient } from "@supabase/ssr";
import { SUPABASE_URL, SUPABASE_PUBLIC_KEY } from "@/lib/env";

/**
 * Клиент для клиентских компонентов ("use client").
 *
 * Использует тот же публичный ключ и тот же cookie-сеанс, что и серверный
 * клиент, поэтому права пользователя совпадают на сервере и в браузере.
 * Секретных значений здесь нет: публичный ключ не является секретом (ТЗ, S5).
 */
export function createSupabaseBrowserClient() {
  return createBrowserClient(SUPABASE_URL, SUPABASE_PUBLIC_KEY);
}
```

### Шаг 3.2.5. Диагностическая страница

Файл `web/src/app/diag/page.tsx`. Страница доступна без входа намеренно:
она показывает состояние анонимной роли. На этапе 3.8 она будет удалена.

```tsx
import { createSupabaseServerClient } from "@/lib/supabase/server";
import { SUPABASE_HOST } from "@/lib/env";

// Страница читает cookie и не должна кэшироваться или prerender-иться.
export const dynamic = "force-dynamic";

/** Объекты, видимость которых проверяется. Порядок соответствует ТЗ. */
const CHECKED_OBJECTS = [
  "patients",
  "doctors",
  "analyses",
  "assignments",
  "app_users",
  "admin_patients",
  "admin_doctors",
  "admin_assignments",
] as const;

type ObjectCheck = {
  name: string;
  count: number | null;
  comment: string;
};

export default async function DiagnosticsPage() {
  const supabase = await createSupabaseServerClient();

  // getUser() проверяет токен на сервере аутентификации.
  // getSession() для серверных проверок не применяется.
  const { data: userData, error: userError } = await supabase.auth.getUser();
  const user = userData.user;

  // Подсчёт строк без передачи самих данных: head = true.
  const checks: ObjectCheck[] = [];
  for (const name of CHECKED_OBJECTS) {
    const { count, error } = await supabase
      .from(name)
      .select("*", { count: "exact", head: true });

    checks.push({
      name,
      count: error ? null : count,
      comment: error ? `${error.code ?? "—"}: ${error.message}` : "запрос выполнен",
    });
  }

  // Роль читается из профиля; для анонимной роли профиль недоступен.
  let roleLabel = "сеанс отсутствует";
  if (user) {
    const { data: profile } = await supabase
      .from("app_users")
      .select("role")
      .eq("user_id", user.id)
      .maybeSingle();
    roleLabel = profile?.role ?? "профиль не найден";
  }

  return (
    <main className="container">
      <h1>Диагностика подключения</h1>
      <p className="muted">
        Служебная страница этапа 3.2. Будет удалена на этапе 3.8.
      </p>

      {userError && (
        <div className="notice notice--error">
          Ошибка проверки сеанса: {userError.message}
        </div>
      )}

      <section className="card">
        <h2>Состояние</h2>
        <div className="table-wrap">
          <table className="table">
            <tbody>
              <tr>
                <th>Проект Supabase</th>
                <td>{SUPABASE_HOST}</td>
              </tr>
              <tr>
                <th>Пользователь</th>
                <td>{user ? user.email : "не выполнен вход"}</td>
              </tr>
              <tr>
                <th>Роль</th>
                <td>
                  <span className="badge">{roleLabel}</span>
                </td>
              </tr>
            </tbody>
          </table>
        </div>
      </section>

      <section className="card">
        <h2>Видимость объектов</h2>
        <p className="muted">
          Запросы выполняются от имени текущего сеанса. Для анонимной роли
          ожидается отказ по каждому объекту: права не выданы (этап 2.4).
        </p>
        <div className="table-wrap">
          <table className="table">
            <thead>
              <tr>
                <th>Объект</th>
                <th>Доступно строк</th>
                <th>Примечание</th>
              </tr>
            </thead>
            <tbody>
              {checks.map((check) => (
                <tr key={check.name}>
                  <td>{check.name}</td>
                  <td>{check.count ?? "—"}</td>
                  <td>{check.comment}</td>
                </tr>
              ))}
            </tbody>
          </table>
        </div>
      </section>
    </main>
  );
}
```

## 5. Проверка результата

### 5.1. Диагностическая страница без входа

```bash
npm run dev
```

Открыть `http://localhost:3000/diag`.

Ожидается:

| Поле | Значение |
|---|---|
| Проект Supabase | `<ref>.supabase.co` |
| Пользователь | `не выполнен вход` |
| Роль | `сеанс отсутствует` |

Таблица видимости: по всем восьми объектам в столбце «Доступно строк» — прочерк,
в примечании — сообщение вида `42501: permission denied for table patients`
(для представлений — `permission denied for view admin_patients`).

Такой результат означает, что подключение установлено, а данные закрыты.

### 5.2. Отсутствие cookie сеанса

В инструментах разработчика браузера (Application → Cookies) для адреса
`localhost:3000` не должно быть cookie с префиксом `sb-`. Они появятся после
входа на этапе 3.3.

### 5.3. Сборка и стиль кода

```bash
npm run build
npm run lint
```

Ожидается успешное завершение; маршрут `/diag` помечен как динамический
(символ `ƒ`), статическая prerender-версия для него не создаётся.

### 5.4. Контроль отсутствия секретов

Из корня репозитория:

```bash
git grep -n "sb_secret_" -- . || echo "секретные ключи не найдены"
git grep -n "service_role" -- web || echo "сервисная роль в коде не используется"
git status --short
```

Ожидается: секретные значения отсутствуют, `web/.env.local` не в индексе.
Упоминания сервисной роли допустимы только в комментариях и документации.

### 5.5. Защита серверного модуля (необязательно)

Временно добавьте в любой клиентский компонент строку
`import { createSupabaseServerClient } from "@/lib/supabase/server";`
и выполните `npm run build`. Ожидается ошибка сборки о недопустимом импорте
серверного модуля. После проверки изменение отменяется.

## 6. Диагностика типовых отклонений

| Наблюдение | Причина | Действие |
|---|---|---|
| Ошибка «Не заданы NEXT_PUBLIC_…» | Не создан `.env.local` либо сервер не перезапущен | Выполнить шаг 3.1.7, перезапустить `npm run dev` |
| Ошибка «Указан локальный адрес Supabase» | В переменной адрес локального стека | Заменить адресом облачного проекта |
| `invalid JWT`, `JWSInvalid` в примечаниях | Публичный ключ нового формата не принят установленной версией библиотеки | Обновить `@supabase/supabase-js` либо использовать legacy-ключ `anon` |
| `Dynamic server usage: cookies` при сборке | Страница не помечена динамической | Добавить `export const dynamic = "force-dynamic"` |
| Ошибка импорта `server-only` | Серверный модуль попал в клиентский компонент | Использовать `client.ts` в клиентских компонентах |
| `Cannot find module 'server-only'` | Пакет не установлен | Повторить шаг 3.2.1 |
| Строки видны анонимной роли | Не выполнены отзыв привилегий и включение RLS | Повторить этап 2.4 и проверку 2.8 |
| Пустая таблица видимости, ошибок нет | Объекты не найдены: опечатка в именах | Сверить список с `docs/DB_STATE.md` |

## 9. Критерии готовности этапа

1. `/diag` открывается и показывает отсутствие сеанса.
2. По всем восьми объектам получен отказ с кодом `42501`.
3. Cookie сеанса в браузере отсутствуют.
4. `npm run build` и `npm run lint` завершаются без ошибок.
5. Секретные значения в репозитории отсутствуют.

серверные действия входа и выхода, страница `/login`, промежуточный слой
