## 1. Цель и результат этапа

Создать работающий каркас приложения на Next.js с TypeScript, привести стартовую
страницу к сине-белому оформлению, настроить игнорирование служебных файлов,
задать параметры подключения к **удалённому** проекту Supabase и убедиться
в его доступности.

**Результат:** `npm run dev` открывает приложение по адресу `http://localhost:3000`;
`npm run build` и `npm run lint` проходят успешно; `npm run check:supabase`
подтверждает, что облачный проект отвечает, а анонимный доступ к данным закрыт.

> Приложение запускается локально, база данных находится в облаке. Это штатный
> режим разработки: обращения к Supabase выполняются по протоколу HTTPS.

## 3. Проектные решения

| Решение | Обоснование |
|---|---|
| Только удалённый Supabase | Все сценарии БД уже выполнены в SQL Editor облачного проекта. Локальная копия не создаётся, расхождение сред исключено. |
| Приложение размещается в подкаталоге `web/` | Сценарии БД и документация остаются в корне репозитория; инициализатор Next.js не конфликтует с существующими файлами. В Vercel указывается Root Directory = `web` (этап 4). |
| Фиксируется мажорная версия 15 (`create-next-app@15`) | Воспроизводимость стенда: состав команд, имена файлов и поведение серверных API постоянны для всех этапов. |
| App Router, TypeScript, каталог `src/` | Серверные компоненты позволяют проверять роль до отрисовки страницы (ТЗ, S6). |
| Tailwind не устанавливается | Требование ТЗ: минимальное оформление, один глобальный файл стилей. |
| Параметры подключения — в `.env.local` | Значения не публикуются; в репозитории хранится только шаблон без значений (ТЗ, D3). |
| Публичный ключ допускается в браузере | Он не является секретом: доступ ограничивают политики RLS (ТЗ, S5). Секретный ключ не используется вовсе (ТЗ, S4). |
| Проверка соединения — отдельный сценарий | Ошибки сети и параметров выявляются до появления клиентского кода, что упрощает диагностику на этапе 3.2. |

> **Замечание о версиях.** В Next.js 16 файл промежуточного слоя называется
> `proxy.ts` вместо `middleware.ts`. Это будет учтено на этапе 3.3; при версии 15
> применяется имя `middleware.ts`. Прочие файлы этапов совпадают.

### Шаг 3.1.7. Параметры подключения к удалённому проекту

**Получение значений в панели Supabase:**

| Значение | Где находится | Примечание |
|---|---|---|
| Адрес проекта | Settings → Data API (или Settings → API), поле **Project URL** | Вид `https://<ref>.supabase.co`. Только облачный адрес. |
| Публичный ключ | Settings → API Keys → **Publishable key** (`sb_publishable_…`) либо вкладка Legacy API keys → **anon public** (`eyJ…`) | Пригоден любой из двух; оба идентифицируют проект и действуют как анонимная роль до входа пользователя. |

Секретный ключ (`sb_secret_…` или `service_role`) **не копируется и не
используется** (ТЗ, S4).

**Шаблон** `web/.env.example` — создаётся и попадает в репозиторий, без значений:

```dotenv
# Публичные переменные. Префикс NEXT_PUBLIC_ означает, что значение
# попадает в браузер, поэтому секретов здесь быть не должно.
# Публичный ключ не является секретом: доступ ограничивают политики RLS.

# Адрес удалённого проекта Supabase, например https://abcdefgh.supabase.co
NEXT_PUBLIC_SUPABASE_URL=

# Публичный ключ: sb_publishable_... либо legacy anon (eyJ...)
NEXT_PUBLIC_SUPABASE_ANON_KEY=

# Сервисный (секретный) ключ не используется ни приложением, ни сценариями
# подготовки данных (ТЗ, S4). Добавлять его в этот файл не требуется.
```

**Рабочий файл** `web/.env.local` — создаётся локально, в репозиторий не попадает:

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://ваш-проект.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=вставьте_публичный_ключ
```

Значения подставляются без кавычек и пробелов; завершающий слеш в адресе
не указывается. После изменения файла сервер разработки перезапускается.

### Шаг 3.1.8. Сценарий проверки удалённого соединения

Создаётся файл `web/scripts/check-supabase.mjs`. Сценарий выполняется вне
Next.js, читает `.env.local` самостоятельно и не требует установленных
библиотек Supabase. Данные не изменяются, сеанс пользователя не создаётся.

```js
/**
 * Проверка доступности удалённого проекта Supabase.
 * Запуск: npm run check:supabase   (из каталога web)
 *
 * Проверяется:
 *   1) доступность службы аутентификации по HTTPS;
 *   2) доступность REST-интерфейса и корректность запрета для анонимной роли.
 *
 * Ожидаемый результат: служба отвечает, данные анонимной роли недоступны.
 */
import { readFileSync, existsSync } from "node:fs";
import { fileURLToPath } from "node:url";
import { dirname, resolve } from "node:path";

const scriptDir = dirname(fileURLToPath(import.meta.url));
const envPath = resolve(scriptDir, "..", ".env.local");

/** Простое чтение файла переменных окружения: строки вида КЛЮЧ=ЗНАЧЕНИЕ. */
function readEnvFile(path) {
  if (!existsSync(path)) {
    console.error(`[ОШИБКА] Не найден файл ${path}. Выполните шаг 3.1.7.`);
    process.exit(1);
  }
  const values = {};
  for (const rawLine of readFileSync(path, "utf8").split(/\r?\n/)) {
    const line = rawLine.trim();
    if (!line || line.startsWith("#")) continue;
    const separator = line.indexOf("=");
    if (separator === -1) continue;
    const key = line.slice(0, separator).trim();
    let value = line.slice(separator + 1).trim();
    if (
      (value.startsWith('"') && value.endsWith('"')) ||
      (value.startsWith("'") && value.endsWith("'"))
    ) {
      value = value.slice(1, -1);
    }
    values[key] = value;
  }
  return values;
}

const env = readEnvFile(envPath);
const projectUrl = (env.NEXT_PUBLIC_SUPABASE_URL || "").replace(/\/+$/, "");
const publicKey = env.NEXT_PUBLIC_SUPABASE_ANON_KEY || "";

if (!projectUrl || !publicKey) {
  console.error("[ОШИБКА] В .env.local не заданы адрес проекта и публичный ключ.");
  process.exit(1);
}

if (/localhost|127\.0\.0\.1|:54321/i.test(projectUrl)) {
  console.error("[ОШИБКА] Указан локальный адрес. Стенд работает только с облачным проектом.");
  process.exit(1);
}

/** Обращение с ограничением времени ожидания. */
async function request(url) {
  return fetch(url, {
    headers: { apikey: publicKey },
    signal: AbortSignal.timeout(10000),
  });
}

async function main() {
  console.log(`Проект: ${new URL(projectUrl).host}`);

  // 1. Служба аутентификации.
  try {
    const response = await request(`${projectUrl}/auth/v1/health`);
    if (!response.ok) {
      console.error(`[ОШИБКА] Служба аутентификации ответила кодом ${response.status}.`);
      console.error("        Проверьте публичный ключ (шаг 3.1.7).");
      process.exit(1);
    }
    console.log("[ОК] Служба аутентификации доступна.");
  } catch (error) {
    console.error(`[ОШИБКА] Соединение не установлено: ${error.message}`);
    console.error("        Проверьте адрес проекта, доступ к сети и настройки прокси.");
    process.exit(1);
  }

  // 2. REST-интерфейс и закрытость данных для анонимной роли.
  try {
    const response = await request(`${projectUrl}/rest/v1/patients?select=id&limit=1`);
    if (response.status === 401 || response.status === 403) {
      console.log("[ОК] REST-интерфейс доступен, анонимной роли данные не выдаются.");
    } else if (response.ok) {
      console.error("[ОШИБКА] Анонимная роль получила данные. Проверьте этап 2.4 (привилегии и RLS).");
      process.exit(1);
    } else {
      console.error(`[ОШИБКА] Неожиданный ответ REST: ${response.status}.`);
      console.error(await response.text());
      process.exit(1);
    }
  } catch (error) {
    console.error(`[ОШИБКА] REST-интерфейс недоступен: ${error.message}`);
    process.exit(1);
  }

  console.log("\nИтог: удалённый проект доступен, параметры подключения заданы верно.");
}

main();
```

## 7. Диагностика типовых отклонений

| Наблюдение | Причина | Действие |
|---|---|---|
| Инициализатор сообщает о непустом каталоге | Каркас создаётся в корне репозитория | Указать каталог `web` |
| Страница без стилей | Не заменён `globals.css` либо удалён импорт | Восстановить шаги 3.1.3–3.1.4 |
| Ошибка «Cannot find module '@/…'» | Изменён псевдоним импортов | Проверить `paths` в `tsconfig.json` |
| `.env.example` не попадает в коммит | Правило `.env*` без исключения | Добавить `!.env.example` |
| `[ОШИБКА] Не найден файл .env.local` | Файл не создан или находится вне `web/` | Выполнить шаг 3.1.7 |
| `fetch failed`, `ENOTFOUND`, `ETIMEDOUT` | Нет доступа к сети, закрыт порт 443, требуется прокси | Проверить соединение; при корпоративном прокси задать `HTTPS_PROXY` либо выполнить проверку вне ограниченной сети |
| Ошибка сертификата при проверке | Прокси подменяет сертификат | Указать доверенный корневой сертификат переменной `NODE_EXTRA_CA_CERTS` |
| Код 401 на шаге проверки аутентификации | Опечатка в публичном ключе либо скопирован секретный ключ | Заново скопировать **публичный** ключ |
| Анонимная роль получила данные | Не выполнены отзыв привилегий и включение RLS | Повторить этап 2.4 и проверку 2.8 |
| Порт 3000 занят | Другое приложение | `npm run dev -- -p 3001` |
