**Файл документа:** `docs/stages/stage_03_3_auth.md`

**Основание:** ТЗ v1.0, раздел 5 (F1, F7), 6 (S6, S8)

---

## 1. Цель и результат этапа

Реализовать вход по адресу и паролю, выход, продление сеанса и серверную
проверку прав. После входа диагностическая страница должна показывать роль
пользователя и фактическую видимость данных согласно матрице доступа.

**Результат:** вход выполняется на `/login`, сеанс хранится в cookie, выход
снимает сеанс, неаутентифицированное обращение к защищённым страницам
перенаправляет на вход. Разделы по ролям создаются на этапе 3.4.

> **Временное решение этапа.** После успешного входа переход выполняется
> на `/diag`, поскольку разделы по ролям ещё не созданы. На этапе 3.4 одна
> строка в серверном действии будет заменена на переход по роли.

---

## 2. Предварительные условия

1. Этап 3.2 выполнен: `/diag` открывается, анонимной роли данные недоступны.
2. Учётные записи созданы и подтверждены (этап 2.3), пароль известен.
3. Самостоятельная регистрация в проекте отключена.

---

## 3. Проектные решения

| Решение | Обоснование |
|---|---|
| Вход выполняется серверным действием | Cookie сеанса записываются на сервере, поэтому сеанс доступен и серверным компонентам, и браузерному клиенту. |
| Промежуточный слой только продлевает сеанс | Проверка прав сосредоточена в страницах (`requireRole`). Единая точка принятия решения упрощает проверку и исключает расхождение правил. |
| В промежуточном слое нет обращений к таблицам | Он исполняется в среде Edge; обращения к данным там избыточны и замедляют каждый запрос. |
| `getUser()` вместо `getSession()` | Подпись токена проверяется сервером аутентификации (ТЗ, S6). |
| Роль берётся из `app_users` | Таблица недоступна пользователю на запись; повысить роль самостоятельно нельзя (ТЗ, S3). |
| Общее сообщение об ошибке входа | Не раскрывается, существует ли указанный адрес. |
| Отказ оформлен отдельной страницей `/denied` | Пользователь получает понятное сообщение, а не пустую страницу или ошибку (ТЗ, F7). |
| `/denied` не использует `requireRole` | Иначе при отсутствии профиля возник бы бесконечный переход: страница отказа сама бы перенаправляла на себя. |
| Выход — обработчик маршрута с методом POST | Изменение состояния не выполняется по ссылке GET; после выхода применяется перенаправление 303. |
| Тип состояния формы вынесен в отдельный файл | В файле с директивой `"use server"` должны оставаться только асинхронные функции. |

### Шаг 3.3.2. Серверный контекст пользователя и проверка прав

Файл `web/src/lib/auth.ts`.

```ts
import "server-only";

import { redirect } from "next/navigation";
import { createSupabaseServerClient } from "@/lib/supabase/server";
import { isAppRole, type AppRole } from "@/lib/roles";

/** Профиль из таблицы app_users. */
export type UserProfile = {
  role: AppRole;
  doctorId: string | null;
  patientId: string | null;
};

export type AuthContext = {
  supabase: Awaited<ReturnType<typeof createSupabaseServerClient>>;
  userId: string;
  email: string;
  profile: UserProfile | null;
  displayName: string;
};

/** Фамилия и инициалы; отчество может отсутствовать. */
function shortName(last: string, first: string, middle: string | null): string {
  const initials = [first, middle]
    .filter((part): part is string => Boolean(part))
    .map((part) => `${part[0].toUpperCase()}.`)
    .join(" ");
  return `${last} ${initials}`.trim();
}

/**
 * Текущий сеанс и профиль. Возвращает null, если вход не выполнен.
 *
 * getUser() проверяет токен на сервере аутентификации. Профиль читается
 * политикой «собственная строка» (этап 2.4), поэтому пользователь не может
 * подменить роль.
 */
export async function getAuthContext(): Promise<AuthContext | null> {
  const supabase = await createSupabaseServerClient();

  const { data: userData } = await supabase.auth.getUser();
  const user = userData.user;
  if (!user) return null;

  const email = user.email ?? "";

  const { data: profileRow } = await supabase
    .from("app_users")
    .select("role, doctor_id, patient_id")
    .eq("user_id", user.id)
    .maybeSingle();

  const profile: UserProfile | null =
    profileRow && isAppRole(profileRow.role)
      ? {
          role: profileRow.role,
          doctorId: profileRow.doctor_id ?? null,
          patientId: profileRow.patient_id ?? null,
        }
      : null;

  // Отображаемое имя. Врач и пациент читают собственную запись справочника;
  // для остальных ролей справочники закрыты, поэтому показывается адрес.
  let displayName = email || "пользователь";

  if (profile?.role === "doctor" && profile.doctorId) {
    const { data } = await supabase
      .from("doctors")
      .select("last_name, first_name, middle_name")
      .eq("id", profile.doctorId)
      .maybeSingle();
    if (data) displayName = shortName(data.last_name, data.first_name, data.middle_name);
  }

  if (profile?.role === "patient" && profile.patientId) {
    const { data } = await supabase
      .from("patients")
      .select("last_name, first_name, middle_name")
      .eq("id", profile.patientId)
      .maybeSingle();
    if (data) displayName = shortName(data.last_name, data.first_name, data.middle_name);
  }

  return { supabase, userId: user.id, email, profile, displayName };
}

/**
 * Допуск к разделу. Применяется в серверных компонентах страниц.
 *
 * redirect() прерывает выполнение, поэтому вызов не помещается в try/catch.
 * Отсутствие профиля и несоответствие роли ведут на страницу отказа с
 * указанием причины.
 */
export async function requireRole(
  allowedRoles: readonly AppRole[]
): Promise<AuthContext & { profile: UserProfile }> {
  const context = await getAuthContext();

  if (!context) redirect("/login");
  if (!context.profile) redirect("/denied?reason=profile");
  if (!allowedRoles.includes(context.profile.role)) redirect("/denied?reason=role");

  return { ...context, profile: context.profile };
}
```

### Шаг 3.3.3. Промежуточный слой продления сеанса

Файл `web/src/middleware.ts` (при использовании каталога `src/` файл размещается
внутри него). В Next.js 16 этот файл называется `proxy.ts`; содержание совпадает.

```ts
import { NextResponse, type NextRequest } from "next/server";
import { createServerClient } from "@supabase/ssr";
import { SUPABASE_URL, SUPABASE_PUBLIC_KEY } from "@/lib/env";

/**
 * Продление сеанса.
 *
 * Токен доступа живёт ограниченное время; при обращении к серверу он
 * обновляется, и новые значения cookie записываются в ответ. Без этого слоя
 * серверные компоненты не смогут сохранять обновлённый сеанс.
 *
 * Проверка прав здесь не выполняется: она сосредоточена в страницах.
 */
export async function middleware(request: NextRequest) {
  let response = NextResponse.next({ request });

  const supabase = createServerClient(SUPABASE_URL, SUPABASE_PUBLIC_KEY, {
    cookies: {
      getAll() {
        return request.cookies.getAll();
      },
      setAll(cookiesToSet) {
        // Сначала значения передаются дальше по цепочке запроса...
        for (const { name, value } of cookiesToSet) {
          request.cookies.set(name, value);
        }
        response = NextResponse.next({ request });
        // ...затем закрепляются в ответе браузера.
        for (const { name, value, options } of cookiesToSet) {
          response.cookies.set(name, value, options);
        }
      },
    },
  });

  // Обращение к серверу аутентификации инициирует обновление токена.
  await supabase.auth.getUser();

  return response;
}

export const config = {
  // Служебные файлы и изображения исключаются: продление сеанса для них не нужно.
  matcher: [
    "/((?!_next/static|_next/image|favicon.ico|.*\\.(?:svg|png|jpg|jpeg|gif|webp|ico)$).*)",
  ],
};
```

### Шаг 3.3.5. Серверное действие входа

Файл `web/src/app/login/actions.ts`.

```ts
"use server";

import { redirect } from "next/navigation";
import { createSupabaseServerClient } from "@/lib/supabase/server";
import type { LoginState } from "./types";

/**
 * Вход по адресу и паролю.
 *
 * Cookie сеанса записываются на сервере. Сообщение об ошибке общее:
 * оно не раскрывает, существует ли указанный адрес.
 */
export async function signInAction(
  _previousState: LoginState,
  formData: FormData
): Promise<LoginState> {
  const email = String(formData.get("email") ?? "").trim();
  const password = String(formData.get("password") ?? "");

  if (!email || !password) {
    return { error: "Укажите адрес электронной почты и пароль." };
  }

  const supabase = await createSupabaseServerClient();
  const { error } = await supabase.auth.signInWithPassword({ email, password });

  if (error) {
    return { error: "Неверный адрес или пароль. Проверьте данные и повторите вход." };
  }

  // ВРЕМЕННО (этап 3.3): разделы по ролям появятся на этапе 3.4,
  // поэтому переход выполняется на диагностическую страницу.
  // На этапе 3.4 эта строка заменяется переходом по ROLE_HOME.
  redirect("/diag");
}
```

### Шаг 3.3.6. Форма входа

"use client";

import { useActionState } from "react";
import { signInAction } from "./actions";
import type { LoginState } from "./types";

### Шаг 3.3.8. Выход

Файл `web/src/app/auth/signout/route.ts`.

```ts
import { NextResponse } from "next/server";
import { createSupabaseServerClient } from "@/lib/supabase/server";

/**
 * Выход. Метод POST: изменение состояния не выполняется по ссылке GET.
 * Код 303 предписывает браузеру перейти на страницу входа методом GET.
 */
export async function POST(request: Request) {
  const supabase = await createSupabaseServerClient();
  await supabase.auth.signOut();
  return NextResponse.redirect(new URL("/login", request.url), { status: 303 });
}
```

### Шаг 3.3.9. Страница отказа

Файл `web/src/app/denied/page.tsx`.

```tsx
import Link from "next/link";
import { redirect } from "next/navigation";
import { getAuthContext } from "@/lib/auth";
import { ROLE_LABELS } from "@/lib/roles";
import { SignOutButton } from "@/components/SignOutButton";

export const dynamic = "force-dynamic";

const REASONS: Record<string, string> = {
  role: "Раздел недоступен для вашей роли.",
  profile: "Для учётной записи не задан профиль. Обратитесь к администратору.",
};

/**
 * Сообщение об отсутствии прав. Проверка requireRole здесь не применяется:
 * при отсутствии профиля это привело бы к бесконечному перенаправлению.
 *
 * В Next.js 15 параметр searchParams асинхронный.
 */
export default async function DeniedPage({
  searchParams,
}: {
  searchParams: Promise<{ reason?: string }>;
}) {
  const context = await getAuthContext();
  if (!context) redirect("/login");

  const { reason } = await searchParams;
  const message = REASONS[reason ?? ""] ?? "Доступ к запрошенному разделу запрещён.";

  return (
    <main className="container">
      <div className="card auth-card">
        <h1>Недостаточно прав</h1>
        <div className="notice notice--error">{message}</div>

        <p>
          Пользователь: <strong>{context.displayName}</strong>
          <br />
          Роль:{" "}
          <span className="badge">
            {context.profile ? ROLE_LABELS[context.profile.role] : "не определена"}
          </span>
        </p>

        <div className="row">
          <Link className="btn btn--secondary" href="/">
            На главную
          </Link>
          <SignOutButton />
        </div>
      </div>
    </main>
  );
}
```

### 5.2. Вход врача и видимость данных

Адрес `clinic.doctor1@example.com`, демонстрационный пароль.
Ожидается переход на `/diag` и следующие значения:

| Объект | Доступно строк |
|---|---|
| `patients` | 3 |
| `doctors` | 1 |
| `analyses` | 9 |
| `assignments` | 3 |
| `app_users` | 1 |
| `admin_patients` | 0 |
| `admin_doctors` | 0 |
| `admin_assignments` | 0 |

1. Нажать «Выйти» на `/diag`. Ожидается переход на `/login`, cookie `sb-…`

2. Без входа открыть `/denied`. Ожидается перенаправление на `/login`.
3. Войти и открыть `/login`. Ожидается перенаправление на `/diag`.

## 6. Диагностика типовых отклонений

| Наблюдение | Причина | Действие |
|---|---|---|
| После входа снова форма входа | Cookie не записались: действие входа выполняется не на сервере | Проверить директиву `"use server"` в `actions.ts` |
| Бесконечные переходы между `/login` и `/denied` | Проверка прав помещена в страницу отказа | Использовать в `/denied` только `getAuthContext` |
| Ошибка «cookies was called outside a request scope» | В промежуточный слой импортирован `lib/supabase/server.ts` | В `middleware.ts` создавать клиент напрямую |
| Ошибка сборки о `server-only` в Edge | То же обстоятельство | Заменить импорт на `createServerClient` |
| `NEXT_REDIRECT` перехвачен и вход «зависает» | `redirect()` вызван внутри `try/catch` | Вынести вызов из блока перехвата |
| Сеанс пропадает через час | Промежуточный слой не подключён или исключён шаблоном `matcher` | Проверить размещение `src/middleware.ts` |
| «Invalid login credentials» при верном пароле | Учётная запись не подтверждена | В панели выполнить Confirm user (этап 2.3) |
| Роль «не определена» | Отсутствует профиль в `app_users` | Повторить шаг 2.3.4 |
| Ошибка типа при `useActionState` | Версия React ниже 19 | Проверить `npm ls react` |
